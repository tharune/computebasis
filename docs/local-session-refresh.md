# Local browser session and public refresh lifecycle

Start `scripts/serve.py --store /absolute/path/outside-git/decisions.sqlite` and open the exact `http://127.0.0.1:<port>` origin. The browser bootstraps its local session automatically; no API key belongs in the page or browser storage. This is a single local application trust boundary, not a user identity system or enterprise authorization service. Optional non-browser clients can still supply a strong `COMPUTE_PRICING_API_KEY` through their environment and send Bearer authentication.

## Browser contract

`POST /v1/session/bootstrap` accepts JSON `{}` from the exact configured loopback Host and Origin, with `Sec-Fetch-Site: same-origin`, an empty Fetch destination and a `cors` or `same-origin` fetch mode. It sets a host-only, HttpOnly, SameSite Strict cookie scoped to `/v1`, lasting at most fifteen minutes, and returns `auth_mode`, `csrf_token`, `expires_at` and explicit local scopes. The response cannot be cached. Cookies use Secure when the configured loopback origin uses HTTPS. The development launcher uses HTTP on the loopback interface only and disables proxy headers and request access logs.

Keep `csrf_token` only in page memory and send `X-Compute-CSRF` on each browser write. Repeated bootstrap on an unexpired session reuses the cookie and original expiry while adding a fresh CSRF hash. A bounded ring of sixteen hashes permits separate active tabs; the server stores no raw CSRF tokens and does not extend the session lifetime. Expired sessions bootstrap afresh. Logout, `POST /v1/session/logout` with JSON `{}` and the current CSRF token, revokes the shared session for all tabs and clears its cookie.

Every cookie-authenticated API call must have the exact configured Host and same-origin Fetch Metadata. Reads may omit Origin, as normal browser fetches do; an Origin that is present must match exactly. Browser writes require the matching Origin and CSRF token. Duplicate Host, Origin, session cookie or CSRF claims fail closed. Newly added write routes require an explicit browser scope; there is no execution scope. No cross-origin credential-sharing policy is installed.

The frontend may renew authentication and retry a read. It must never automatically replay a write after a 401, cancellation or an unknown response, because an earlier effect may already have completed. Preserve the draft and let the user resume or reconcile it. Bootstrap should be coalesced within the page, and logout must finish before resuming the workspace, so delayed cookie responses cannot race a newer session.

## Refresh contract

The launcher reads the reviewed source admission, bounded collection plan and `examples/auto-refresh.json`; corresponding command-line options select explicit replacements. Its default lifecycle enables startup and periodic reads. `--no-auto-refresh` leaves only manual collection. `create_app` callers default to no background reads and must explicitly supply `auto_refresh` to enable the lifecycle. Imports, construction and all tests perform no live reads.

Automatic collection is limited to ten admitted anonymous source roles: GetDeploying, Azure retail prices, AWS regional public price files, OpenRouter model prices, ECB reference FX, Hugging Face model metadata and public recipes, Energinet day-ahead power, GPUHunt provider catalogs and national GB grid-carbon context. Only configured scopes are attempted. Disabled, expired, missing-rights, credential-required, unsupported and private-source configurations are held before network access; the lifecycle does not discover or grant permissions to another feed. Observe, retain and benchmark checks run before each read and again before persistence; policy replacement during the read prevents retention. Carbon refresh has a thirty-minute floor; its gCO2/kWh forecast and estimated actual never enter the compute-price benchmark.

The runner processes due scopes sequentially and prevents overlapping cycles. In automatic mode, manual and background calls for the same explicit scope share one in-flight worker. A cancelled HTTP caller does not cancel the underlying bounded read or release its collection permit early. Shutdown stops new scope attempts and drains the active worker. Two process-local collection permits, existing per-host locks and transport limits remain enforced. This is not distributed scheduling or quota coordination, and the app installs no system job.

The POSIX local lifecycle helper holds an outside-Git advisory process lock around its lifecycle commands; a competing command fails safely before checking or signaling a process. It verifies its recorded PID's exact script/store/port and the health instance before requesting graceful termination. It waits at most sixty seconds for process exit, preserving metadata and reporting `draining` if the worker remains alive. It never treats a closed health listener as process exit, never force-kills, and blocks a replacement start while the owned process still drains. Repeated stop waits for the existing request rather than sending another signal. Direct external signals and older unrelated launchers do not participate in this helper's lock.

Cadences are operational configuration. They never modify source observation dates, license permissions or freshness rules. Failure backoff doubles from its configured initial delay to its cap; a longer transport cooldown or Retry-After still takes precedence. Source-local failures do not abort other due scopes. Success resets the failure counter and delays the same scope's next attempt, including when a manual call produced the update.

Authenticated `GET /v1/market/refresh/status` returns `enabled`, `running`, `scope_count` and `scopes`. Each scope records its source/filter digest, waiting/in-progress/ready/held/failed state, attempt/success/next-due dates, safe error code, consecutive failures, collection snapshot ID and native record counts. No response bodies, credentials or network exception text appear in status. The frontend refreshes `GET /v1/market/index` to display new immutable snapshots; this GET performs no collection. Rows retain source roles, rights, age, incomplete-catalog warnings and fair display caps. A refreshed tariff is still an advertised claim, metadata is still discovery, and neither becomes a firm compute price or inventory proof.

Normalized collection snapshots and dated decisions stay in the explicit SQLite location outside Git. The application retains no raw HTTP archive through this lifecycle. Broad redistribution, routing resale, model execution, trades, leases, payments and deployment authorization remain outside these read and paper-evaluation contracts.

## Pure portfolio routes

Authenticated `GET /v1/portfolio/template` returns a blank typed contract with no holdings, prices, funds or evidence. `POST /v1/portfolio/evaluate` applies the pure portfolio evaluator and stores its canonical request/result/versions in a `portfolio` snapshot. The response uses the existing `{snapshot_id, created_at, versions, result, execution_enabled}` envelope; replay uses `/v1/decisions/{snapshot_id}`. These routes create no live reservation, funding commitment or execution permission.
