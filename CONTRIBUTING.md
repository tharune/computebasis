# Development and publication

Only the maintainer publishes commits to the default branch. Suggestions may be submitted for review; repository write access is not granted to outside contributors.

Before publication:

1. Run the complete offline test suite and the documented example.
2. Verify numerical units, freshness behavior, capacity and funding assumptions.
3. Review the complete candidate tree and Git metadata for private data, personal information, secrets and unlicensed source material.
4. Publish with the maintainer's account and a concise description of the resulting behavior.

Changes to schemas, factor ownership, model assumptions and financial calculations need explicit documentation and meaningful regression tests. Source observations and approved policies have separate roles. Preserve unknowns and exclusions instead of creating convenient defaults.

Examples are invented for this project. Do not upload customer records, source spreadsheets, private correspondence, original research attachments or licensed vendor payloads. Maintain an evidence store outside the repository for any future admitted live data.

Tests and examples run locally. This repository does not run untrusted pull-request code on a self-hosted runner.
